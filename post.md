# Урок: POST-запросы в PHP

## Цели урока
К концу урока ученик должен уметь:
1. Объяснить, чем POST отличается от GET и когда его использовать.
2. Читать данные из `$_POST`, `$_FILES` и `php://input`.
3. Безопасно принимать и сохранять загруженные файлы.

---

## 1. Введение: зачем нужен POST

Переходим к более защищённому способу передачи данных на сервер — **POST-запросу**.

**Главное правило:** POST передаёт данные в теле запроса (Body), а не в URL.

Благодаря этому мы можем передавать:
- чувствительные данные (пароли, логины, токены, ключи) — они не попадают в логи сервера, историю браузера и кэши;
- большие объёмы данных (например, JSON с тысячами записей) без ограничения длины URL;
- файлы (PDF, CSV, изображения) в виде `multipart/form-data`.

> **Важная оговорка для учеников:** POST *безопаснее* GET в смысле "не светится в адресной строке и логах", но сам по себе он **не шифрует** данные. Реальную защиту от перехвата даёт только HTTPS. Это стоит проговорить отдельно, чтобы не создать у учеников ложное чувство защищённости.

### Мини-сравнение с GET (для повторения)

| | GET | POST |
|---|---|---|
| Где данные | В URL (query string) | В теле запроса |
| Ограничение размера | Есть (зависит от браузера/сервера) | Практически нет |
| Кэшируется браузером | Да | Нет |
| Можно добавить в закладки | Да | Нет |
| Подходит для файлов | Нет | Да |

## 2. Анатомия POST-запроса

POST-запрос состоит из:
- **URL** — адрес, на который отправляется запрос;
- **Заголовки (Headers)** — метаданные запроса: `Content-Type`, `Authorization` и др.;
- **Тело запроса (Body)** — сами данные: JSON, XML, form-data и т.д.

```
POST /input.php HTTP/1.1              ← request line, метод изменился на POST
Host: mysite.ru
User-Agent: Mozilla/5.0
Content-Type: application/x-www-form-urlencoded
Content-Length: 29                    ← сервер должен заранее знать размер тела,
                                         чтобы понять, где тело заканчивается
                                       ← пустая строка отделяет заголовки от тела
username=admin&password=12345
```

---

## 3. Заголовок Content-Type: как сервер понимает формат данных

### `application/x-www-form-urlencoded`
Поведение по умолчанию для любой HTML-формы без файлов.
Данные кодируются так же, как в URL: пробелы становятся `+` или `%20`, спецсимволы экранируются.

- В HTTP: `name=Alex+Smith&age=25`
- В PHP: автоматически парсится в `$_POST['name']` и `$_POST['age']`.

### `multipart/form-data`
Используется, когда нужно передать файлы или тяжёлые данные. Данные **не кодируются** (чтобы не раздувать вес файла), а разбиваются на блоки, разделённые уникальной строкой — **boundary** (границей).

⚠️ **Важно:** в HTML-форме обязательно нужно указать `enctype`:
```html
<form method="POST" enctype="multipart/form-data">
```

### `application/json`
⚠️ **Важный нюанс для учеников:** PHP **не умеет** автоматически парсить JSON в `$_POST` — массив останется пустым, даже если данные реально пришли в теле запроса. Для JSON нужен отдельный способ чтения (см. Сценарий 3 ниже).

## 4. Практика: как получать POST-данные

### Сценарий 1. Обычная форма
```php
$username = $_POST['username'] ?? '';
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    echo "Привет, " . htmlspecialchars($username);
}
```
> Обратите внимание учеников на `htmlspecialchars()` — это защита от XSS при выводе пользовательских данных обратно на страницу. Хороший повод напомнить про доверие к вводу пользователя вообще.

### Сценарий 2. Обработка файла (multipart)
```php
if (isset($_FILES['avatar'])) {
    $file = $_FILES['avatar'];

    $tmpPath = $file['tmp_name'];               // временный файл на сервере
    $destination = __DIR__ . '/uploads/' . $file['name'];

    if (move_uploaded_file($tmpPath, $destination)) {
        echo "Файл успешно загружен!";
    }
}
```

**Анатомия `$_FILES['avatar']`:**
```php
$_FILES['avatar'] = [
    'name'     => 'photo.jpg',       // оригинальное имя файла
    'type'     => 'image/jpeg',      // MIME-тип (по мнению браузера, НЕ проверено!)
    'tmp_name' => '/tmp/phpYzdqkD',  // путь к временному файлу на сервере
    'error'    => 0,                 // код ошибки (0 = ошибок нет)
    'size'     => 12345              // размер файла в байтах
];
```

**Ключ `error` — коды состояния** (проверять всегда, до работы с файлом):

| Код | Константа | Значение |
|---|---|---|
| 0 | `UPLOAD_ERR_OK` | всё прошло успешно |
| 1 | `UPLOAD_ERR_INI_SIZE` | файл превысил лимит `upload_max_filesize` в php.ini |
| 2 | `UPLOAD_ERR_FORM_SIZE` | файл превысил лимит `MAX_FILE_SIZE`, заданный в самой форме |
| 3 | `UPLOAD_ERR_PARTIAL` | файл загружен только частично |
| 4 | `UPLOAD_ERR_NO_FILE` | пользователь отправил форму, не выбрав файл |
| 6 | `UPLOAD_ERR_NO_TMP_DIR` | отсутствует временная папка на сервере |

### Сценарий 3. Ловим JSON (продвинутый уровень)
```php
$rawBody = file_get_contents('php://input');
$data = json_decode($rawBody, true);
echo $data['username'];
```
> Стоит показать на практике: если ученик попробует `$_POST['username']` при `Content-Type: application/json`, ничего не выведется. Это частая точка путаницы.

## 5. Безопасность при загрузке файлов

### 5.1. `name` — ОПАСНО, никогда не доверяй напрямую
Это оригинальное имя файла на компьютере пользователя. Злоумышленник может назвать файл `../../../etc/passwd` или `script.php`.

**Правило:** всегда генерировать имя файла на бэкенде, а оригинальное имя сохранять только в базу данных — для отображения пользователю.

```php
$safeName = uniqid('img_', true) . '.jpg';
```

### 5.2. Проверять реальный тип файла, а не ключ `type`
Ключ `$_FILES['avatar']['type']` присылает браузер — его легко подделать. Реальный тип файла нужно проверять на сервере через расширение **Fileinfo**:

```php
$finfo = finfo_open(FILEINFO_MIME_TYPE);
$realType = finfo_file($finfo, $_FILES['avatar']['tmp_name']);

if ($realType !== 'image/jpeg' && $realType !== 'image/png') {
    die("Можно загружать только картинки!");
}
```

### 5.3. Хранить файлы правильно
В идеале папка с загрузками должна лежать **выше корневой директории сайта** (выше `public_html`), чтобы к файлам нельзя было обратиться напрямую по URL. Файлы отдаются пользователю только через специальный PHP-скрипт.

Если по условиям задачи файлы всё же должны лежать в публичной папке (`/uploads/`) — обязательно нужно настроить Nginx/Apache так, чтобы в этой папке было **запрещено исполнение любых скриптов** (иначе загруженный `script.php` можно будет запустить через браузер).

### 5.4. Итоговый чек-лист безопасной загрузки файла
1. Проверить `error` (должен быть `0`).
2. Проверить размер файла (`size`) на разумный лимит.
3. Проверить реальный MIME-тип через Fileinfo, а не поле `type`.
4. Сгенерировать безопасное имя файла (`uniqid()`), не использовать `name` напрямую.
5. Сохранять файлы вне публичного корня или запретить исполнение скриптов в папке загрузок.
6. Только после всех проверок — `move_uploaded_file()`.

---

## 6. Итог урока (проговорить с учениками)

- POST передаёт данные в теле, а не в URL — подходит для чувствительных и больших данных.
- `Content-Type` определяет, как сервер разберёт тело запроса — это ключевая идея всей темы.
- `$_POST` работает для форм, но **не** работает для JSON — нужен `php://input`.
- Любая загрузка файла от пользователя — потенциальная уязвимость. Никогда не доверять `name` и `type` из `$_FILES` напрямую.
