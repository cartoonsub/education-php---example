X-Topic: зачем-нужен-post

Тело запроса вместо адресной строки

Главное правило: POST передаёт данные в теле запроса (Body), а не в URL. Это открывает три возможности, недоступные GET-запросу.

🔒 Чувствительные данные

Пароли, логины, токены и ключи не попадают в логи сервера, историю браузера и кэши.

📦 Большие объёмы

JSON с тысячами записей передаётся без ограничения длины URL.

📎 Файлы

PDF, CSV, изображения — в виде multipart/form-data.

⚠️ Но не забывайте

POST сам по себе не шифрует данные. Реальную защиту от перехвата даёт только HTTPS.

Content-Type: application/json

Ловушка с JSON

PHP не умеет автоматически парсить JSON в $_POST. Массив останется пустым — даже если данные реально пришли в теле запроса.

script.php
$rawBody = file_get_contents('php://input');
$data = json_decode($rawBody, true);
echo $data['username']; // вот так — а не через $_POST
X-Topic: практика

Получаем данные от формы и файла

Сценарий 1 · обычная форма
$username = $_POST['username'] ?? '';
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    echo "Привет, " . htmlspecialchars($username);
}
Сценарий 2 · файл (multipart)
if (isset($_FILES['avatar'])) {
    $file = $_FILES['avatar'];
    $tmpPath = $file['tmp_name'];
    $destination = __DIR__ . '/uploads/' . $file['name'];
    if (move_uploaded_file($tmpPath, $destination)) {
        echo "Файл успешно загружен!";
    }
}

X-Topic: безопасность-загрузок

Загрузка файла — потенциальная уязвимость

name — опасно

Злоумышленник может назвать файл ../../../etc/passwd или script.php. Никогда не используйте его напрямую для сохранения.

type — не проверено

Присылает браузер, легко подделать. Проверяйте реальный MIME-тип через finfo_file().

безопасное сохранение
$finfo = finfo_open(FILEINFO_MIME_TYPE);
$realType = finfo_file($finfo, $_FILES['avatar']['tmp_name']);
if ($realType !== 'image/jpeg' && $realType !== 'image/png') {
    die("Можно загружать только картинки!");
}
$safeName = uniqid('img_', true) . '.jpg'; // генерируем имя сами
